# @avasapp/agent-bridge

## 0.6.0

### Minor Changes

- 1e989d3: `screen.snapshot` takes `{format: "text"}` for one line per element (`button #save "Save plant" disabled`, with `index=N` on lines that repeat and `@x,y` on lines with no testID, text, label or placeholder) instead of JSON with a rect per element: about a fifth of the size. It also takes `{kinds: ["button", "input"]}` to keep only those kinds and `{within: target}` to keep only elements under a target in the tree. An empty filtered result says what matched nothing, a long label is never cut, and `--out` with `{"format":"text"}` writes the text (`--json` with it is an error).
  
  Behaviour change: `agent-bridge call screen.snapshot` and the MCP `screen_snapshot` tool now print the text form by default. For the old JSON pass `--json` (or `--out`) to `call`, or `{"format": "json"}` as the argument (`args: [{"format": "json"}]` over MCP). `connect()`, `bridge.call` and flows still get JSON unless they ask for text.
- 6534b6b: New opt-in `@avasapp/agent-bridge/device` entry with `deviceTools({ NetInfo, Notifications, navigation, time })`. `device.openUrl` delivers an incoming deep link to the app's Linking listeners (and makes `getInitialURL` return it), returning the route the app ended on when you pass the navigation container. `device.appState` fires AppState change listeners and sets `AppState.currentState`. `device.offline` makes every `fetch` and XHR fail like no network, mocks included, and tells NetInfo; requests it fails show in `net.log` as `(device offline)`. `device.notification` calls expo-notifications' received or (with `{tapped: true}`) response listeners. `device.setTime` (with `time: true`) shifts `Date.now()` and `new Date()`. `device.restore` undoes all of it and reports `restored: true` if anything was undone, and `bridge.pending` lists what is set. The Ably and socket.io adapters now also log what the app sends (`channel.publish`, `socket.emit`) in `realtime.log` with `sent: true`; `socket.emit` is logged once per call as its argument list, payloads are copied and cut, and credential-looking keys show as `[redacted]` unless `realtime.log` gets `{full: true}`; `createRealtimeTap` gets `sent()` and `@avasapp/agent-bridge/realtime` exports `tapOutgoing` for custom taps.
- 08aff63: `agent-bridge run` now runs several flows: pass files, a directory (its `*.flow.mjs`) or a glob (globs only match `*.flow.mjs`), and it runs them in order on one connection, prints a pass/fail line for each and a summary, and exits 1 if any failed. `--bail` stops at the first failure, `--grep <text>` picks flows by name or by path relative to where you ran, `--keep` leaves the app as a flow left it, and `--reporter json|junit` writes a report for CI: on stdout (with step lines and a flow's `console.log` on stderr) or to a file with `--out <file>`, which needs `--reporter`. A flow file that won't load, a failed connect and a `--grep` with no match show up as failed testcases in the report instead of crashing before it. JUnit uses the folder as the classname and relative file paths, so same-named flows in different folders stay apart.
  
  Behaviour change: every flow now ends with `bridge.restore`, not only flows that declare a scenario, so a failed flow can't leave the app dirty for the next one. Through a session this also undoes changes you made by hand before `run`; pass `--keep` to skip it. `runFlow` does the same (`{ keep: true }` opts out). A flow's own `step('undo', 'bridge.restore')` is no longer needed. Errors the closing restore reports are printed but don't count for `--strict`.
  
  Running one flow now also shows that closing `restore` step. If the app stops answering, the error is printed at once and the remaining flows are skipped with that reason.
  
  Flows get an `expect` helper (`expect.text`, `expect.gone`, `expect.route`, `expect.result`) that fails with a readable message (`expect.result` takes a `RegExp` to match a string and rejects `Date`, `Map` and other class instances), and a failed flow prints what was on screen (`screen.snapshot` and `router.current`).
- 97ff9e0: `agent-bridge mcp` runs an MCP server on stdio, for agents that prefer MCP tools to a shell: `claude mcp add agent-bridge -- ./node_modules/.bin/agent-bridge mcp`. Each tool the app exposes becomes an MCP tool (`screen.snapshot` is `screen_snapshot`) that takes `args`, an array of its arguments, and `full`. It uses the project's session (and stays on that one, never another server's `mcp-*` session), or starts one and runs `bridge.restore` when the server exits (`--keep` skips that). If its session is stopped, the next call says so once and the call after that uses a new session. It sends `notifications/tools/list_changed` whenever the list a client received is out of date, including when the app starts after the agent, and always lists an `agent_bridge_status` tool that says why it is not connected. Results over 32 KB come back as a summary unless `full` is true, `screen.capture` images are sent as image content by their real type, and session errors such as `may or may not have run` pass through unchanged. See [the CLI docs](https://github.com/avas-app/agent-bridge/blob/main/docs/cli.md#mcp-server).
- 2f8a9eb: Network mocks can match more exactly. `net.mock` takes `{path: "/orders/:id"}` (the whole path on any host, query ignored; `:name` is one segment, `*` the rest), `{body: {...}}` (the JSON request body contains these keys) and `{graphql: "GetUser"}` (the request's `operationName`, from the JSON body or `?operationName=`), alone or with `url` and `method`. A bare string still matches any URL containing it, and `net.mock` and `net.mocks` now return `matches`, the mock in words. An unknown key in a match is now an error instead of being ignored. `net.mockFromLog` on a GraphQL request now only answers that operation, where it used to answer every request to the endpoint; when the logged body wasn't kept it says so in a `warning`. Strict mode lists blocked GraphQL requests by operation and names mocks that matched the URL but not the body.
  
  New `net.waitFor(match, {timeoutMs, status, sinceId})` waits for a matching request to finish and returns its entry. `net.entry` now shows request and response headers, with credential values cut unless you pass `{full: true}`: any header whose name contains auth, cookie, token, secret, session, password, signature or api-key (so `apikey`, `x-auth-token` and `x-amz-security-token` too). Authorization keeps only its scheme word, the rest at most 4 characters and a quarter of the value. `net.waitFor` waits for the response body to be read and matches a GraphQL `?operationName=` on a GET. `networkTools({logSize})` sets how many requests the log keeps. An XHR aborted just after `send()` is no longer sent when no mock answers it, and one aborted before `send()` is sent as normal. `path` also treats `:name` as a parameter only as a whole segment, takes a trailing slash either way, matches `/` on a bare host, and tries the percent-decoded URL. A `body` that is empty once serialised (`{a: undefined}`) is refused. A body or GraphQL mock no longer makes `fetch(Request)` calls with a binary body wait for a body read. A handler mock with `times: 1` now answers one of two requests in flight, and `shadows` skips mocks that have `times`.
- d785078: `screen.press` no longer treats a pressable that wraps an input or two or more other controls (a tap-to-dismiss-keyboard screen, a modal backdrop around Cancel and OK) as one big button holding all the text under it. A button built from wrapper components, a card with one icon button, and a row with inline text links keep their text. When the handler it called belongs to an ancestor, the reply says `via: "ancestor"`. `screen.fill` now works on uncontrolled inputs (including Fabric and `value: undefined`), fires `onEndEditing`, clears with `""`, and takes `{type:true}` to type one character at a time, waiting for a render after each, with `"\n"` as the Enter key. For an uncontrolled input the reply's `element.value` is what was written, and it carries a `warning` if the text could not be written natively. `router.navigate`, `push` and `replace` now return the route the app ended on (an object, not the href string) once the screen has rendered, throw on `+not-found`, and warn when the path or query is not the href's, or when the navigation container has not mounted.
- a30731f: New adapter for apps on `@react-navigation/native` without expo-router: `navTools(navigationRef)` from `@avasapp/agent-bridge/react-navigation`. It adds `nav.navigate`, `nav.push`, `nav.replace`, `nav.popTo`, `nav.back`, `nav.popToTop` and `nav.current`. Each navigation tool waits for the new screen and returns the route the app ended on (`name`, `params`, `path`, `stack`, `canGoBack`), adds a `warning` when the screens asked for (including a nested `{screen}` chain) are not at the end of the path or a push/replace changed nothing, and throws on an unknown route name. `nav.push` and `nav.replace` throw when the focused navigator is tabs or a drawer, and `nav.popToTop` does nothing at a stack's first screen instead of popping a parent. In React Navigation 7, `nav.navigate` pushes unless the screen is already focused; use `nav.popTo` to return to an earlier one. Pass `getStateFromPath` and a `linking` object with a `config` to let `nav.navigate` take a path like `/post/7` or a URL with one of `linking.prefixes`; apps with a static config or `linking: { enabled: 'auto' }` should use route names. The tools are named `nav.*` so they do not clash with `router.*`. `init` now writes a commented `navTools(navigationRef)` line for these apps, replacing the old sample tools.
- 840cd82: Two new adapters. `@avasapp/agent-bridge/redux` (`reduxTools(store, {redact})`) gives `redux.list`, `get` (the state or a path, with `pick` and `keys`), `dispatch` (a plain `{type, payload}` action), `set` (merge into a slice), `commit` and `restore`. Wrap your root reducer in `bridgeReducer()` so `set` and `restore` can replace the state (inside redux-persist's `persistReducer`, so the saved copy follows a restore; in release builds it returns your reducer unchanged). Without it they fail and say so. The replace action carries no state, so loggers and devtools never see tokens. `redux.set` snapshots and restores per slice and skips a slice the app changed since (returned as `{restored, skipped}`); `redux.dispatch` snapshots the whole state. Array slices are refused. `@avasapp/agent-bridge/jotai` (`jotaiTools(store, {name: atom}, {redact})`) gives `jotai.list` (each atom `read-write` or `read-only`), `get`, `set`, `commit` and `restore`. Restore reads each atom back and reports a write that didn't take, skips an atom the app changed since, and snapshots `atomWithStorage` at its stored value; `jotai.set` refuses action atoms and `atomWithReducer`. A `redact` key that matches no slice or atom logs a warning once. Both snapshot on the agent's first change, `bridge.restore` and `bridge.pending` include them, and `redact` is by slice or atom name (`{auth: ['token']}`, or `{session: true}` for all of it). They use their own prefixes, so they never clash with `store.*`. `agent-bridge init` adds both, commented out, when it finds `@reduxjs/toolkit`, `redux` or `jotai`.
- 07b2280: `bridge.restore` can now undo MMKV and persisted-store changes after the app reloads or crashes, when you are in a session. The session keeps what `mmkv.set` and `mmkv.delete` (string values) and `store.set`/`store.call` on a zustand store with `persist` changed, and hands it to the new runtime after the reload, so a fake token you wrote before `app.reload` is still removed by `bridge.restore` and `session stop`. Nothing is rewritten at reload time: the app boots on your value. The next call reports `kept N undos across the reload`, and names values the app changed since your write, which are left alone. Other restores (stores without `persist`, queries, mocks, `onRestore`) are still lost with the usual warning. The journal stays in the session's memory and is never logged. New adapter hooks `journal`, `adopt` and `journalRev` on a `*.restore` tool let your own area opt in; `bridge.adopt` is internal: it is hidden from the tool list and refused for any caller that does not bring the session key (not access control: the runtime takes the first non-empty key it sees on each load, so two sessions on one app do not take each other's journal, and a client that is first can still read the journal, which only holds what `store.get` and `mmkv.get` already show); the journal is sent only on the reply to the call that changed it, so `bridge.journal` no longer exists. An area that never becomes ready is retried twice, then reported once as `could not re-arm after the reload` and dropped. `session stop` right after a reload still restores. Depends on the session retry change (the app-reload and lost-reply handling). Persisted stores are journaled, compared and restored per top-level key: a key you did not change is never rewritten (so a boot-time write like `launchCount` no longer hides your undo), and a key that is not plain JSON (`Set`, `Date`, class instance) or that `partialize` renames is named as `not kept across reload`. MMKV entries record the instance `id` when it has one and are skipped on a mismatch; a `mmkv.delete` whose key is simply absent after the reload is reported as already back unless the same `id` is confirmed. On MMKV v4 (no instance `id`) a `mmkv.delete` is not undone after a reload. When a persisted area and a non-persisted one were both changed, `kept N undos` can hide that the non-persisted one is lost: check `bridge.pending` after a reload.
- 339290c: New `screen.setValue(target, value)` sets a Switch, Slider, Picker or SegmentedControl, and returns the value the app shows once it has rendered, with a warning when the app did not take it (not for a Slider, whose `value` is often only a start value). A Switch takes true or false. A Slider takes a number within `minimumValue` and `maximumValue` (0 and 1 when unset) and on its `step`, and gets `onSlidingStart`, `onValueChange` and `onSlidingComplete` in that order; a Slider with only `onSlidingComplete` works. A Picker takes one of its `Picker.Item` values (read from its children, as the native picker does) and gets the item index too. A SegmentedControl takes one of its `values` through `onChange` and `onValueChange`. A wrong type or value is an error that lists the options. `screen.press` on a Switch (found by its native switch host or `role="switch"`, so one whose `value` has not loaded yet counts) toggles it with `onValueChange` instead of pressing the row around it (the reply says `via: "onValueChange"`). `screen.press(target, {long:true})` long presses, calling `onPressIn`, `onLongPress` and `onPressOut`, and errors when there is no `onLongPress` on the element or before the first element that handles presses. `{scroll:true}` on `screen.press`, `screen.fill` and `screen.setValue` now pages the largest vertical `FlatList`, `SectionList` or `FlashList` for a row it has not rendered yet, outward from where it is, waiting for rows to render after each page (up to 40 pages or 10 seconds; `{scroll:{timeoutMs}}` changes the time). When nothing matches it scrolls the list back to where it was, and the error says how far it got and which lists it left alone. Paging can trigger `onEndReached` and `onViewableItemsChanged`. `{scroll:true}` with `{at:[x,y]}` is refused. `screen.waitFor` does not page lists: wait for the list, then use `press`, `fill` or `setValue` with `{scroll:true}`. Pressing something inside a react-native-gesture-handler tap or long press `GestureDetector` fails with a message saying its callbacks run on the UI thread, and no longer falls through to a press handler further up.
- 39d5a5c: Two new adapters. `@avasapp/agent-bridge/async-storage` (`asyncStorageTools(AsyncStorage)`) gives `asyncStorage.list` (with `{limit, prefix}` and values cut to 200 characters), `get`, `set`, `delete` and `restore`. `@avasapp/agent-bridge/secure-store` (`secureStoreTools(SecureStore, knownKeys, options)`) gives `secureStore.list` (the keys you pass, with set and length), `get`, `set`, `delete` and `restore`; `get` returns `[redacted, N chars]` unless called with `{full:true}`, and `bridge.pending` never shows its keys or values. Pass the same `options` your app gives SecureStore (such as `keychainService`), as one object or a function of the key; they apply to every call, including restore. Keys with `requireAuthentication` are not read by `list`. Both restore what the agent changed, awaiting each async write, and `bridge.restore` and `bridge.pending` include them. A key the app wrote after the agent did is left alone and returned in `skipped`. The originals are kept in memory, so restore before reloading: `app.reload` now names the pending restores it will lose in a `lost` field. `agent-bridge init` adds both, commented out, when it finds the packages.

### Patch Changes

- c7ae306: `screen.snapshot`, `screen.waitFor {gone}`, `screen.findText` and `screen.press` treat unfocused native tabs (react-native-screens `Tabs.Host`, as used by expo-router `NativeTabs`, on iOS and Android) as hidden, like screens under a stack. If the host's selected tab matches no mounted tab screen (or several), nothing is hidden. Where nothing can be measured (React Native's old architecture, or a test renderer), the screen tools that need positions (`snapshot`, `press`, `fill`, `scroll`, `waitFor`) fail with a message saying so instead of returning an empty screen; `snapshot {all: true}` and `findText` still return text and test IDs, with no rects.
  
  A command run from a monorepo root finds the one session started in an app folder under it. Lookup goes downward only: a session started at the root is not found from an app folder, and a session in a nested checkout (a folder with its own `.git`) or in a package of its own is never matched from above. With several app sessions under the root, the command connects directly as before; pass `--session` to pick one. "No single session matches" now says what it looked for, including when `--metro`, `--device` or `--transport` was given.
- 8bd76d0: A session no longer runs a call twice when its reply is lost (the app reloaded or the connection dropped mid-call). Read-only tools such as `screen.snapshot`, `screen.waitFor` and `store.get` are repeated on the new connection (a `screen.waitFor` repeat gets only the time left, and a `{gone: true}` wait is not repeated after a reload); any other tool, including `bridge.restore` and app tools that only end in `.log`, fails with `the app reloaded during <tool>; it may or may not have run` (`the app disconnected` or `the connection dropped` when no reload is known), with the reload warning attached. That message also comes when the reconnect itself fails, with the reason added. The session's 5 s health check no longer takes the app's logged errors, so they reach the next real call tagged with the tool they followed, not `bridge.ping`. A `timeoutMs` in the options of `screen.waitFor` or `webview.waitFor` (`screen.waitFor '["Done", {"timeoutMs": 15000}]'`) longer than the call timeout now stretches it (2 s past it, 7 s for `webview.waitFor`, at most 10 minutes), in the CLI, sessions and `connect()`, so the app's own timeout error arrives first. Other tools' `timeoutMs` arguments are left alone.
- ebaa493: A reset or failed connect on a session socket no longer crashes the process with an uncaught error. `agent-bridge mcp` and the session daemon now report it as a normal "session isn't answering" or "closed the connection" error, and the "closed the connection" message now includes the socket error (for example `ECONNRESET`) when there was one. This is the likely cause of the occasional uncaught `ECONNRESET` in tests.

## 0.5.0

### Minor Changes

- acc2fd6: `agent-bridge init` sets up an app in one command: `npx @avasapp/agent-bridge init`. It installs the package with the app's package manager, writes a dev-only `src/dev/agent-bridge.tsx` wired for what it finds (Expo, expo-router, TanStack Query, WebViews; zustand and MMKV as comments, since they often hold tokens; a TODO for Ably or socket.io), scaffolds `flows/smoke.flow.mjs`, adds the agent skill, and prints the two lines to mount it. It asks once whether to wire `networkTools()`, and never prompts with `--json`, `--yes` or without a terminal, listing the open choice in the report instead. `--dry-run` changes nothing, and a second run skips existing files (`--force` regenerates only the ones you haven't edited). See [the CLI docs](https://github.com/avas-app/agent-bridge/blob/main/docs/cli.md#init).
  
  Flows now go in `<app>/flows/<name>.flow.mjs`, and the example app's flows were renamed to match. `run`'s help no longer lists `.ts` flows, which were never tested.
- 62ba7b1: `screen.press` works on controls with no `onPress` that are screen-reader operable, such as swipe-to-confirm buttons: it calls `onAccessibilityAction` with `activate`, as VoiceOver and TalkBack do on a double tap, and the reply says `via: "accessibilityAction:activate"`. `screen.press(target, {action: "increment"})` sends any other action the element declares, and `screen.snapshot` lists them as `actions` and shows activatable controls as buttons.

### Patch Changes

- dbb4eab: When nothing listens on the Metro address, the CLI and `connect()` now look for Metro on ports 8081-8090, 8100-8199 and running sessions' addresses (within a second, only after the failure) and name what they found with its apps, plus the `--metro` flag or `AGENT_BRIDGE_METRO` value to use. "No app is connected" and "No app matches" add the likely causes, and `devices` fails with the same hint instead of printing "No apps connected." when Metro isn't there.
- d1f385e: The docs, skill and example now say `npx @avasapp/agent-bridge` instead of `npx agent-bridge`. The unscoped `agent-bridge` on npm is an unrelated package, so `npx agent-bridge` without this package installed downloads and runs someone else's code.
- 1217860: `queryTools` takes any TanStack Query client structurally (`QueryClientLike`), so `queryTools(useQueryClient())` typechecks in an app without a tsconfig `paths` entry for `@tanstack/query-core`.

## 0.4.2

### Patch Changes

- 577fd6a: A session no longer switches to another app when it reconnects. It used to re-run discovery and attach to whatever single app was connected, so after the app went away its calls could land in a different app on the same Metro. Reconnects now only accept the app the session started on (same name and platform, and the same debugger target over CDP; its deviceId changes on every reload), skip an app another session owns, and otherwise fail with `<app> is not connected; connected: …` until it comes back. `--device` matching several apps is now an error that lists them instead of picking the first (an exact match still wins). `Using session "<name>"` on stderr now names the app and Metro too. Closes #69.
  
  A call over CDP now ends at its timeout even when the debugger never answers the evaluate, as the old runtime's socket does after a JS reload; a session on CDP used to hang there for good instead of reconnecting.
- 6c7afa4: `screen.waitFor` takes `{scroll:true}`, like `press` and `fill`: a match that is rendered but off screen (below the fold of a `ScrollView`) is scrolled into view and returned, instead of timing out as an off-screen near miss. Without it, waitFor still matches on-screen elements only, and a timeout with an off-screen near miss now points at `{scroll:true}`. `{gone:true}` with `{scroll:true}` is refused. Closes #68.

## 0.4.0

### Upgrading from 0.3

These change what existing calls return or accept; details are in the entries below.

- `query.get` errors on a key that isn't cached instead of returning `null`; `query.refetch` returns `{ matched, refetched, data }` instead of the data.
- In flows, `step(label, tool, [a, b])` now spreads a single array as the argument list, like `agent-bridge call`; wrap it (`[[a, b]]`) to pass one array.
- `screen.*` only sees the focused screen: elements on screens underneath, inactive tabs and content under a modal no longer match (`screen.snapshot {all:true}` still lists them). `screen.findText` matches the snapshot's joined text.
- `agent-bridge call` prints results over 32 KB as a summary unless `--full` or `--out` is given; a bare argument starting with `@` is a file path; several argument words are each an argument.
- `net.mocks` cuts response bodies over ~2 KB (`{ full: true }` for whole ones).
- `store.set` and `store.call` return only what changed, not the whole store.
- `connect()` and one-off CLI calls fail after 15 s when Metro doesn't answer, instead of hanging.

### Minor Changes

- eebfd42: CLI: `agent-bridge call <tool> @args.json` reads the arguments from a file (`@-` for stdin), so a value over the shell's ~128 KB argument limit no longer fails with `Argument list too long`. A file follows the inline rules: an array is the argument list, any other value is one argument. With several words, each is one argument and `@feed.json` is that file's JSON (`call net.mock '"/feed"' @feed.json`). `call --batch` lines accept `@file` as their argument list. A missing file or invalid JSON fails with an error naming the path.
  
  Behaviour changes: a bare argument starting with `@` is now a file path, not a string (pass such a string as JSON: `'"@user"'`), and `call` with several argument words now sends each as an argument instead of ignoring all but the first.
- 9ba7799: CLI: `agent-bridge call --batch` reads `tool args` lines from stdin and prints one JSON line per call over a single connection (`--stop-on-error`, `--full`, `--out <dir>`; exits 1 if a call failed), and `agent-bridge repl` is an interactive prompt on the same loop with history, tab completion and `.time`/`.tools`/`.pending`/`.restore` dot commands. With stdin not a terminal, `repl` behaves like `--batch`.
  
  In batch and REPL input, arguments that start like JSON (`[`, `{`, `"`) but don't parse are reported as an error instead of being sent as a string; `call` itself is unchanged.
- b722069: `query.get` takes a last `{ pages: [from, to] }` to return only those pages of an infinite query (with `totalPages`), or `{ path: "pages.0.items" }` to return only the value there. `net.mocks` now cuts response `json` and `body` over ~2 KB like `net.log` does and marks the mock `truncated: true`; `{ full: true }` returns them whole (**behaviour change** for anything reading big mock bodies from `net.mocks`). A mock matched by a regex URL now lists the regex instead of `{}`. Fixes a CDP session dying when the app's JS thread was busy for over 1.5 s (for example while another client sent a multi-MB value): the health ping's timeout became an unhandled rejection in the session daemon.
- 6518dae: `agent-bridge call` has `--out <file>`, which writes the result to a file and prints its size and top-level shape. A result over 32 KB now prints as a JSON summary (`resultTooLarge`, `bytes`, `shape`, `hint`) unless `--full` or `--out` is given; **behaviour change** for scripts that parse big `call` output (add `--full`). Flows and the client API still return full values. Fixes results being cut off through a session: a value containing U+2028 or U+2029 (common in scraped text) was split by the session socket's line reader and arrived as invalid JSON.
- 30ef813: Network log and mocks: log entries carry `startedAt` (epoch ms) and `net.log` takes `{ since }`. `net.entry <id>` and `net.log { full: true }` return whole bodies instead of ~2 KB, and `net.mockFromLog <id> [patch]` turns a logged response into a mock, deep-merging a patch. `net.mock` documents that the newest mock wins, takes `options.priority` (higher first, negative for a fallback) and reports `shadows` when it will be tried before an agent mock it also matches.
- 1f67933: A session now notices when the app reloaded and says which pending restores were lost: `app reloaded; N pending restores lost: store, query` comes back with the next call, failed or not (`agent-bridge call` prints it as a warning, `timed()` has it as `notice`, `AgentBridgeCallError` as `notice`), in `agent-bridge run` output, and again in `session stop`. Every reply carries the id of the JS bundle load and the areas with pending undo state (`pending` on a `*.restore` tool), so a reload is caught on the next reply and Fast Refresh is not mistaken for one. On Expo, calls to a reloaded app fail at once instead of timing out. New `app.reload` tool reloads the app's JS (through Expo's `reloadAppAsync` when available, see the patch note below); a session never runs it twice and waits for the new bridge.
- bed11f0: Show what `bridge.restore` will undo and let apps add their own undos. New `bridge.pending` lists each area's pending restore (for stores, the snapshot against the current value, redacted and truncated). `session stop --dry-run` prints the same and keeps the session; `session stop --keep` warns about snapshots still pending. New `store.commit` drops a store's snapshot so the current value becomes the baseline. New `onRestore(fn, label?)` export registers an undo from an app tool; `bridge.restore` runs it once via the new `app.restore`, and `bridge.pending` lists it under `app`. The store tool descriptions now say when the snapshot is taken.
- 68142d5: New `router.dismiss` and `router.dismissAll` tools close route-based modals. `router.back`'s description now says it only pops the navigator and leaves modals and sheets the app renders itself open; the README recommends registering a `modal.close` tool for those. `RouterLike` gains optional `dismiss`, `dismissAll` and `canDismiss`; a router without them makes the two tools throw a clear error.
- de337cf: New `screen.capture` tool takes a PNG screenshot and returns `{path}` (or `{base64}` with `{base64:true}` when small) using `react-native-view-shot`, only if the app already has it; the bridge does not depend on it. Without it the tool errors and points to agent-device, `xcrun simctl io` or `adb exec-out screencap -p`. Closes #11.
- 1c99220: `screen.snapshot`, `screen.findText`, `screen.press`, `screen.fill` and `screen.waitFor` now see only the focused screen: unfocused tabs and native-stack screens, content under an open modal, `display: none` and accessibility-hidden subtrees are skipped, and the result says how many elements (`hidden`) were left out. `screen.snapshot {all:true}` still lists everything and marks hidden ones. New `screen.scroll` (to a target, `{toEnd}`, `{toStart}`, `{by}`, optionally `{within}`) and `screen.refresh` (calls the RefreshControl's `onRefresh`), and `{scroll:true}` on `screen.press` / `screen.fill`. Behaviour change: elements on screens beneath the top one no longer match targets, so a press that only worked by picking a hidden duplicate now needs `{all:true}` to see it.
- d904592: `screen.press` and `screen.fill` reject unknown target keys instead of matching everything. New `{at:[x,y]}` target presses icon-only buttons by point. `{index}` now also works as a trailing options argument, and the ambiguity error shows a concrete example. `screen.press(target, {force:true})` presses a disabled element on purpose.
- 1d30aa7: `screen.findText` and `screen.waitFor` match the same joined text `screen.snapshot` shows (nested `Text` is one string), and `screen.findText` also matches accessibility labels (`{labels:false}` for text only). A miss lists near misses, including elements that are off screen. `screen.snapshot` shows `checked`, `selected` and `expanded` (from `accessibilityState` / `aria-*`, and a `Switch`'s value) and lists views named only by an accessibility label.
  
  Behaviour changes for existing callers: `screen.findText` now matches the snapshot's text, which collapses whitespace, drops icon glyphs and joins a button's several `Text` parts with spaces, so `exact:true` compares against that one string. Text on an inactive tab or screen is now not found at all (before: found, with `onScreen: 0`). Matches also carry a `field`, and `findText` results for a miss may carry `nearMisses`.
- 1d5bdae: Tool arguments no longer go wrong silently when a JSON array is spread into them. `query.get`, `query.refetch`, `query.list`, `query.invalidate` and `query.unpin` take a key flat (`["todos", 1]`) or wrapped (`[["todos", 1]]`). `query.list` adds `isStale`, `isInvalidated`, `dataUpdatedAt`, `errorUpdatedAt` and `fetchStatus`, and takes a key prefix. `store.get` takes its path as a dotted string, an array of segments or separate arguments, and a last `{ pick: [...] }` or `{ keys: true }` returns only some fields. `query.set` and `query.pin` reject a key that isn't an array. A tool definition can set `maxArgs` so a call with extra arguments fails; `query.set`, `query.pin`, `query.unpinAll`, `query.restore`, `store.list` and `store.restore` do, other tools are unchanged.
  
  Breaking changes:
  
  - `query.get` errors on a query that isn't cached (with similar keys) instead of returning null.
  - `query.refetch` returns `{ matched, refetched, data }` instead of the data, and errors when nothing matches or nothing can be refetched.
  - In flows, `step` treats a single array argument as the whole argument list, as `agent-bridge call` does. A step that passed one array to a tool, `step('s', 'cart.setItems', [a, b])`, now spreads it; wrap it to keep the old behaviour: `[[a, b]]`. `call` is unchanged.

The DOM tools work like `screen.*` inside the page (open shadow roots and same-origin iframes included; only the first origin plus `allowedOrigins`, as reported by native load events and `onMessage` URLs, never by the page; `null` origins refused unless allowed), the message tools log and fake the page ↔ app traffic, and page `console.error`, uncaught errors and unhandled rejections go to `bridge.logs`, labelled as page output. ### Patch Changes

- c00ee1e: On Android, a ScrollView or FlatList with a RefreshControl showed up twice in `screen.snapshot` (the refresh layout and the ScrollView inside it both carry the testID), so `{within: '<testID>'}` and other targets naming it failed as ambiguous. It is one element now. A FlatList no longer reports `value: "[object Object]"` (VirtualizedList's context value).
- 44f2283: `app.reload` now reloads through Expo's own `reloadAppAsync` (`globalThis.expo`, Expo SDK 51+) and falls back to `DevSettings.reload()` in apps without Expo. In Expo Go, `DevSettings.reload()` left the reloaded bundle without Expo's native modules ("Cannot find native module 'ExpoAsset'", "main has not been registered") until the app was relaunched. Closes #52.
- 0c7372f: Docs: recommend the installed bin (or `bunx`) over `npx` so npm config warnings stay out of the agent's output, and point timing checks at `agent-bridge run`.
- 81ee974: `net.unmock`, `net.restore` and `query.restore` (so `bridge.restore` and `session stop`) now reset queries whose data came from an agent mock, instead of leaving fake data in the cache where a failing real refetch would keep it. A query counts as mocked when its fetch succeeded while an agent mock answered a request. `query.restore` now returns `{ unpinned, refetched, mockedCleared }`.
  
  Attribution is per request: a query is marked when a request its query function started synchronously was answered by an agent mock. A request started after an await, behind an async interceptor or in a retry is unattributable, so every query fetching then is marked and reset on restore even if real (an observed one refetches once). Infinite queries stay marked until reset; app and scenario mocks aren't tracked.
- aae43ce: Realtime: an Ably message from `realtime.emit` now carries the fields ably-js sets on a real one (`action`, `serial`, `version`, `annotations`, besides `id` and `timestamp`; `version` follows `serial` and `timestamp` as in ably-js), and passing `event` instead of `name` is an error rather than an empty event name. The tool description says what to pass per adapter: Ably `{ name, data }`, socket.io the event name as the channel and the arguments after it (new `emitUsage` option on `createRealtimeTap` for other libraries).
- 984d116: Calls use the running session even when Metro is on a non-default port. With no `--metro`/`--device`/`--session`, `call`, `tools` and `run` use the one session started from the same project (nearest `package.json`), so a session from another project is never picked up by accident. `--metro`, `--device`, `--session` and `AGENT_BRIDGE_*` still reach any session. With several matching sessions the call fails and lists them (pass `--session <name>`). Every command that goes through a session prints `Using session "<name>"` on stderr.
- 0972cf2: A session's reconnect after an app reload can no longer hang forever. Opening a connection (Metro discovery, the websocket upgrade, the CDP handshake, Expo's hello) is now time-bounded, per transport (Expo's socket, then CDP): 12 s per reconnect attempt in a session daemon, 15 s for `connect()` and one-off CLI calls. A stuck reconnect no longer blocks `call`, `session stop` or SIGTERM: calls fail with `The app is gone (...)` or `app not connected; reconnecting`, the daemon retries on its 5 s health check and on the next call until the idle timeout (every 300 ms inside the reload window), and stopping gives `bridge.restore` one bounded reconnect attempt before cutting the attempt in flight. Behaviour change: `openConnection` and `connect()` reject with `Timed out after N ms opening a connection to Metro` where they used to hang. Closes #59.

## 0.3.0

### Minor Changes

- f118441: Scenarios: named setups the app defines, such as a locally signed-in user, passed as `useAgentBridge({ scenarios })`. A scenario's options are a JSON Schema, and `scenario.apply` rejects options that don't fit, unknown keys included, before anything changes. An agent lists them with `agent-bridge scenarios` and applies one with `scenario.apply`. A flow declares what it needs (`export const scenario = 'signedIn'`), and `agent-bridge run` applies it first and runs `bridge.restore` afterwards, even when the flow fails. `run --scenario <name>` adds one to any flow.
