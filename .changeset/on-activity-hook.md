---
'@avasapp/agent-bridge': minor
---

New opt-in activity hook: set `AGENT_BRIDGE_ON_ACTIVITY="<shell command>"` (or pass `--on-activity "<command>"` to `session start`, `call`, `run`, `repl` or `mcp`) and agent-bridge runs that command after a tool call, at most once a minute per process (and per session). It runs in the project directory, in its own process group, with its output discarded, and a command still running after 30 seconds is stopped with everything it started, also when a one-off call has already exited. It never runs for the session's health check or `bridge.ping`. A failing or slow command doesn't change or delay the call; its first failure is reported once (on stderr, or in the session log). A one-off call exits before its command ends, so it leaves the failure in a small file in the state directory and the next call in that project prints it. Use it to keep something alive while an agent works, such as a leased simulator. Through a session, the variable is read where the session starts and the session runs the command for every client's calls; a client with the variable set whose session was started without it warns once to restart the session. `--on-activity` on a client adds a command run by that client. The command appears in warnings and in process lists, so keep secrets out of it. Nothing changes without the variable or flag, and an app can't set it.
