New adapter for apps on `@react-navigation/native` without expo-router: `navTools(navigationRef)` from `@avasapp/agent-bridge/react-navigation`. It adds `nav.navigate`, `nav.push`, `nav.replace`, `nav.popTo`, `nav.back`, `nav.popToTop` and `nav.current`. Each navigation tool waits for the new screen and returns the route the app ended on (`name`, `params`, `path`, `stack`, `canGoBack`), adds a `warning` when the screens asked for (including a nested `{screen}` chain) are not at the end of the path or a push/replace changed nothing, and throws on an unknown route name. `nav.push` and `nav.replace` throw when the focused navigator is tabs or a drawer, and `nav.popToTop` does nothing at a stack's first screen instead of popping a parent. In React Navigation 7, `nav.navigate` pushes unless the screen is already focused; use `nav.popTo` to return to an earlier one. Pass `getStateFromPath` and a `linking` object with a `config` to let `nav.navigate` take a path like `/post/7` or a URL with one of `linking.prefixes`; apps with a static config or `linking: { enabled: 'auto' }` should use route names. The tools are named `nav.*` so they do not clash with `router.*`. `init` now writes a commented `navTools(navigationRef)` line for these apps, replacing the old sample tools.
