`agent-bridge mcp` runs an MCP server on stdio, for agents that prefer MCP tools to a shell: `claude mcp add agent-bridge -- ./node_modules/.bin/agent-bridge mcp`. Each tool the app exposes becomes an MCP tool (`screen.snapshot` is `screen_snapshot`) that takes `args`, an array of its arguments, and `full`. It uses the project's session (and stays on that one, never another server's `mcp-*` session), or starts one and runs `bridge.restore` when the server exits (`--keep` skips that). If its session is stopped, the next call says so once and the call after that uses a new session. It sends `notifications/tools/list_changed` whenever the list a client received is out of date, including when the app starts after the agent, and always lists an `agent_bridge_status` tool that says why it is not connected. Results over 32 KB come back as a summary unless `full` is true, `screen.capture` images are sent as image content by their real type, and session errors such as `may or may not have run` pass through unchanged. See [the CLI docs](https://github.com/avas-app/agent-bridge/blob/main/docs/cli.md#mcp-server).
